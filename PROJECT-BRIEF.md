## 1. الرؤية في سطر واحد

منصّة عربية/إنجليزية يدخل إليها أي شخص — مهما كان مستواه التقني — فيبني سيرة ذاتية تجتاز أنظمة ATS عبر خطوات واضحة، كل حقل فيها مشروح ومعه مثال، ثم يطبعها أو يحمّلها بالعربية أو بالإنجليزية.

**المستخدم المستهدف:** خريج جديد لا يعرف كيف يكتب التواريخ، وموظف بخبرة 15 سنة لا يعرف لماذا تُرفض سيرته. **كلاهما يجب أن ينجح دون قراءة دليل.**

**اسم المشروع المقترح:** `seera` (سِيرة). غيّره إن رغبت.

### لماذا لا باك-إند منفصل (NestJS/Express)؟

لأن هذا المنتج **قراءة/كتابة على قاعدة بيانات واحدة + توليد ملفات**، بلا معالجة ثقيلة ولا عملاء متعددين. الباك-إند المنفصل هنا يضاعف كلفة النشر على CranL ويضيف طبقة CORS وتزامن أنواع بلا مقابل. **لكن** الكود يُبنى بمعمارية طبقية (`services` / `repositories` مستقلة عن Next.js) بحيث لو احتجت لاحقًا تطبيق موبايل أو API عام، تُستخرج الطبقة كخدمة `Hono` في أقل من يوم.

> إن أصررت على الفصل: استخدم **Hono + Drizzle** كخدمة مستقلة، لا NestJS — الأخير ثقيل ومبالغ فيه لهذا الحجم.

## 5. تجربة المستخدم — التفصيل

### 5.1 المعالج (Builder)

شريط تقدّم أفقي أعلى الصفحة (أرقام + علامة ✓ للمكتمل)، والخطوات:
`1 المعلومات الشخصية → 2 الملخص → 3 الخبرات → 4 التعليم → 5 المهارات → 6 الشهادات → 7 اللغات → 8 أقسام إضافية → 9 المراجعة والتصدير`

قواعد المعالج:

- **حفظ تلقائي** (debounce 1.5 ثانية) + مؤشر «تم الحفظ ✓». المستخدم لا يفقد شيئًا أبدًا.
- التنقل حر بين الخطوات (ليس خطيًا إجباريًا)، لكن الخطوة الناقصة تُعلَّم بنقطة كهرمانية.
- **كل خطوة يمكن تخطيها** عدا المعلومات الشخصية.
- معاينة حيّة: على الشاشات الكبيرة لوحة يمين/يسار ثابتة تُظهر الملف كما سيُطبع. على الجوال زر عائم «معاينة» يفتحها كـ Sheet.
- زر ثابت أسفل الشاشة: `السابق` و `التالي` — كبير وواضح.

### 5.2 نمط الحقل الموحّد (أهم تفصيل في المنتج)

كل حقل، بلا استثناء، يُبنى بمكوّن واحد `<FieldWithExample>` يعرض:

```
┌────────────────────────────────────────────────────┐
│ المسمى الوظيفي *                          [؟]      │  ← Label + نجمة + Tooltip للقاعدة
│ ┌────────────────────────────────────────────────┐ │
│ │ مثال: مطوّر واجهات أمامية                      │ │  ← placeholder
│ └────────────────────────────────────────────────┘ │
│ 💡 انسخ المسمى حرفيًا من الإعلان الوظيفي           │  ← قاعدة قصيرة دائمة الظهور
│ ▸ شاهد مثالًا كاملًا                               │  ← Collapsible، بداخله نص جاهز
│    [ استخدم هذا المثال ]                           │  ← يملأ الحقل ليعدّله المستخدم
└────────────────────────────────────────────────────┘
```

النصوص كلها مصدرها `src/lib/constants/field-guides.ts` المشتق من `ATS-CRITERIA.md`.

### 5.3 حقل التاريخ

مكوّن `<MonthYearPicker>` = `Select` شهر + `Select` سنة + `Checkbox` «أعمل هنا حاليًا». **ممنوع** تقويم يومي. فوق كل مجموعة تواريخ يظهر Callout ثابت: _«اكتب الشهر والسنة فقط — لا تكتب اليوم»_. راجع القسم 4 في `ATS-CRITERIA.md` للتفاصيل والتحققات.

### 5.4 الأقسام الديناميكية

في الخطوة 8: زر `+ إضافة قسم جديد` يفتح Dialog يطلب: العنوان بالعربي، العنوان بالإنجليزي، ونوع التخطيط (نقاط / عناصر بتواريخ / فقرة). ثم يُدرج القسم ويصبح قابلًا لإعادة الترتيب بالسحب مع بقية الأقسام، وقابلًا للإخفاء والحذف. تحذير ATS يظهر إذا كان العنوان غير قياسي.

### 5.5 المراجعة والتصدير (الخطوة 9)

- بطاقة **ATS Score** بشريط ملوّن + قائمة «أصلح هذا» كل بند فيها زر ينقل للحقل المعني.
- حقل اختياري: «الصق نص الإعلان الوظيفي» → يعرض الكلمات المفتاحية الناقصة.
- أربعة أزرار كبيرة واضحة:

|               | العربية             | English                   |
| ------------- | ------------------- | ------------------------- |
| **طباعة**     | `طباعة بالعربي`     | `Print in English`        |
| **تحميل PDF** | `تحميل PDF بالعربي` | `Download PDF in English` |

- زر إضافي: `إرسال نسخة إلى بريدي`.
- كل ضغطة تُسجّل صفًا في `exports` وتُحدّث حالة السيرة إلى `completed` عند أول تصدير ناجح.

## 6. الطباعة وتوليد الـ PDF

1. مسار `/print/[resumeId]?lang=ar` يرندر HTML نظيفًا بالكامل: بلا هيدر، بلا تنقّل، بلا ألوان، عمود واحد، مع `@media print { @page { size: A4; margin: 20mm 18mm } }`.
2. **زر الطباعة** → يفتح المسار في نافذة مخفية ويستدعي `window.print()`. تحكم كامل للمستخدم وصفر كلفة سيرفر.
3. **زر تحميل PDF** → `POST /api/export/pdf` → Puppeteer يفتح نفس المسار بتوكن مؤقت → `page.pdf({ format: 'A4', printBackground: false })` → يُرفع إلى S3 → يُعاد رابط موقّع صالح 15 دقيقة.
4. **الخطوط:** تُضمَّن محليًا في `public/fonts` (Noto Naskh Arabic + Liberation Sans) وتُحمَّل عبر `@font-face` قبل `page.pdf` — انتظر `document.fonts.ready`.
5. اسم الملف: `{Name}_{JobTitle}.pdf` بعد تنظيفه من المسافات والرموز.
6. **Dockerfile** يجب أن يثبّت Chromium وخطوط العربية:
   ```dockerfile
   RUN apt-get update && apt-get install -y chromium fonts-noto-core fonts-noto-cjk --no-install-recommends
   ENV PUPPETEER_EXECUTABLE_PATH=/usr/bin/chromium
   ```
7. المرحلة 8 (اختيارية لكن موصى بها): تصدير **DOCX** عبر مكتبة `docx` — بعض أنظمة ATS تقرؤه أفضل من PDF، خصوصًا في المحتوى العربي.

## 7. لوحة التحكم (Admin)

### 7.1 الإحصائيات — بطاقات + رسوم

بطاقات: إجمالي المستخدمين • إجمالي السير • السير المكتملة • **معدل الإكمال %** • عدد الطباعات بالعربي • عدد الطباعات بالإنجليزي • متوسط ATS Score • مستخدمون جدد (7 أيام).
رسوم: خط زمني للتسجيلات والتصديرات (آخر 30 يومًا) • عمودي للمقارنة بين العربي والإنجليزي • قمع (Funnel): سجّل → أنشأ سيرة → أكمل → صدّر.
فلتر فترة موحّد أعلى الصفحة: 7 / 30 / 90 يومًا / مخصص.

### 7.2 جدول السير الذاتية (متكامل)

TanStack Table عبر shadcn data-table:

- **الأعمدة:** المستخدم | البريد | عنوان السيرة | الحالة | ATS | آخر تحديث | مرات التصدير (ar/en) | إجراءات
- **بحث** فوري (debounced) في الاسم والبريد وعنوان السيرة
- **فلاتر:** الحالة، نطاق التاريخ، نطاق ATS، لغة التصدير
- **فرز** على كل عمود + **ترقيم من جهة السيرفر** (server-side pagination)
- **تحديد متعدد** + إجراءات جماعية (حذف)
- **تصدير البيانات:** `CSV` و `XLSX` — يحترم الفلاتر المطبّقة حاليًا
- **CRUD:** عرض (Sheet بكل التفاصيل) • تعديل (العنوان/الحالة/الدور) • حذف منطقي مع Dialog تأكيد يكتب فيه الأدمن كلمة `حذف` • فتح معاينة السيرة
- كل إجراء أدمن يُسجَّل في `audit_log`

### 7.3 جدول المستخدمين

نفس النمط: بحث، فلترة بالدور، تغيير الدور، تعطيل الحساب، عدد السير لكل مستخدم.

## 9. النشر على CranL

1. **Database** → PostgreSQL → انسخ `DATABASE_URL`.
2. **S3 Storage** → أنشئ bucket باسم `seera-exports` → احفظ المفاتيح.
3. **Emails** → اضبط المرسل وانسخ بيانات SMTP.
4. **Applications → Application from Git** → اربط مستودع GitHub → المنفذ `3000` → الصق متغيرات البيئة → Deploy.
5. (اختياري) **Templates → Drizzle Gateway** لإدارة قاعدة البيانات بواجهة رسومية.

```env
DATABASE_URL=
JWT_SECRET=              # 32+ حرفًا عشوائيًا
NEXT_PUBLIC_APP_URL=
S3_ENDPOINT= S3_BUCKET= S3_ACCESS_KEY= S3_SECRET_KEY=
SMTP_HOST= SMTP_PORT= SMTP_USER= SMTP_PASS= MAIL_FROM=
PUPPETEER_EXECUTABLE_PATH=/usr/bin/chromium
```

`src/lib/env.ts` يتحقق من كل ما سبق بـ Zod ويُفشل الإقلاع إن نقص أي منها.
